Evaluation protocols

让每一轮改进
都有可比较的证据

以下四套协议是本站整理的实验设计建议。先选择研究问题，再固定数据、基线、指标和预算；执行前应在仓库中冻结具体配置。

离线自训练与合成数据持续学习与时间演化交互反馈与策略改进智能体反思与反馈记忆
Protocol 01 / offline-self-training

离线自训练与合成数据

收益来自模型生成的有效新监督，还是额外训练、筛选或教师信号？

数据设置
固定版本的 Amazon Reviews 或 MovieLens；训练、验证、测试严格分离，合成与筛选仅使用允许的训练信息。
必备对照
  • 冻结的初始模型（第 0 轮）
  • 仅真实数据继续训练
  • 等量随机增强或重采样
  • 固定教师蒸馏
  • 单轮生成与多轮闭环
报告指标
  • 预先确定的 Recall@K 与 NDCG@K
  • 每轮相对第 0 轮的变化
  • 覆盖率与长尾表现
  • 训练时间、生成成本与总计算量
控制变量
  • 使用相同 backbone、候选集合、负采样和调参预算
  • 分别报告等更新步数与等计算预算对照
  • 固定轮数和停止规则，测试集不得选择最佳轮次
  • 至少 3 个独立随机种子，报告均值、离散程度与配对差异
  • 消融合成、选择、过滤、教师刷新与真实数据混合比例
  • 保留每轮数据校验值、模型 checkpoint 与运行配置
主要风险：自生成偏差可能被循环放大；多轮中挑最优测试分数会夸大提升。

本站建议协议；尚未收录此协议的测量记录。

Protocol 02 / continual-temporal

持续学习与时间演化

模型能否适应新的用户兴趣与物品，同时控制遗忘和更新成本？

数据设置
带时间戳的 KuaiRand、MIND 或 Amazon；采用按时间推进的训练窗口与未来测试窗口，逐窗口披露可用信息。
必备对照
  • 静态模型
  • 每个窗口从头重训
  • 仅新窗口微调
  • 历史回放
  • 带蒸馏或记忆约束的增量更新
报告指标
  • 逐窗口 Recall@K / NDCG@K 或任务指定点击指标
  • 新用户与新物品分组表现
  • 历史任务性能变化
  • 更新时间、峰值显存与存储开销
控制变量
  • 先预测再更新，按时间记录训练数据可见范围
  • 统一窗口长度、回放容量和更新频率
  • 冻结预处理与物品可用时间，防止未来统计泄漏
  • 同时报告全量重训与等预算基线
  • 记录新旧物品候选池及冷启动处理方式
主要风险：随机切分和跨窗口使用未来信息会掩盖真实漂移；全量重训的资源优势必须单独报告。

本站建议协议；尚未收录此协议的测量记录。

Protocol 03 / interactive-policy

交互反馈与策略改进

利用交互反馈更新策略后，长期效用是否改善，且不由环境假设单独驱动？

数据设置
Open Bandit Dataset 用于单步离策略评估；KuaiRec / KuaiRand 配合明确的交互环境用于模拟实验，两种结果分开展示。
必备对照
  • 随机或流行度策略
  • 固定监督排序器
  • 上下文 bandit
  • 固定策略不更新
  • 同交互预算的强化学习策略
报告指标
  • 累计奖励与平均单步奖励
  • 会话长度或退出率（明确环境定义）
  • IPS / SNIPS / DR 估计及不确定性
  • 覆盖率、多样性和用户分组差异
  • 交互样本量与策略更新成本
控制变量
  • 区分真实随机日志、离策略估计与模拟反馈
  • 统一推荐是否可重复、会话终止规则与奖励定义
  • 冻结训练环境，使用独立测试用户及多套环境参数
  • 检查支持集覆盖、权重裁剪和有效样本量
  • 不得把点击提升自动解释为满意度或长期价值提升
主要风险：策略可能利用模拟器漏洞；缺少支持集时离策略估计不能识别目标策略效果。

本站建议协议；尚未收录此协议的测量记录。

Protocol 04 / agent-feedback

智能体反思与反馈记忆

反思、记忆或规划更新是否改善后续推荐，还是仅增加调用次数和推理预算？

数据设置
ReDial 或带文本元数据的推荐数据；固定可检索物品库和用户信息，人工反馈、历史标签与 LLM 模拟反馈分别标注。
必备对照
  • 相同基座模型的单次推荐
  • 等调用次数但无反思
  • 有记忆但无更新
  • 随机或通用反思
  • 独立的检索与排序基线
报告指标
  • 候选库内 Recall@K / NDCG@K
  • 推荐实体有效率
  • 按预注册量表的偏好一致性与任务成功率
  • 每会话调用次数、token、费用与延迟
  • 跨用户或跨领域迁移表现
控制变量
  • 固定模型版本、提示词、温度、工具与候选池
  • 隔离测试用户记忆，禁止把测试标签写回反思库
  • 进行无反思、无记忆和等成本消融
  • 若用 LLM 评价，披露评审模型并做独立人工抽检
  • 将用户模拟器与被测推荐器分开，并改变模拟器检验稳健性
  • 分别评估会话内适应与跨会话持续改进
主要风险：同一模型同时生成用户反馈、反思和评分会形成自我确认；对话流畅不等于推荐有效。

本站建议协议；尚未收录此协议的测量记录。

协议如何落地

使用固定的数据版本与文件校验值，记录所有随机种子和环境依赖。公开结果时同时提交初始轮与更新轮、逐 seed 数值、总成本及证据链接。协议中的具体窗口、轮数、候选数和预算由实验者预先确定并披露。
